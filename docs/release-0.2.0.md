# Urbitwarden 0.2.0

This desk works with the independently maintained Connect desk on stock Vere 4.6 / Zuse 408. Dated client runs include SSO, local unlock and encrypted sync in official Bitwarden CLI 2026.10.0, Chrome extension 2026.10.0, signed macOS desktop 2026.10.0 and an unchanged official iOS 2026.10.0 source build in Simulator. The current candidate's CLI also completed encrypted attachment upload/download and JSON export/import; the desktop completed a native master-password change, new-password unlock and sync. [Client evidence](client-support.md) identifies which source revision each run covered.

On 2026-10-24, a separate running 408k ship installed this desk and Connect through `|install` from the stable publisher. Both were `%live` with no queued update, and the vault config and Connect info endpoints returned JSON with HTTP 200. The receiver was not enrolled as a vault; the client results above come from their own dated runs.

An older alpha vault without a per-installation account ID receives one on update. Its old Bitwarden sessions and Connect grants are revoked, so clients must complete fresh owner approval and SSO. The in-place upgrade retained encrypted items and wrapped keys. A portable age-encrypted vault snapshot restored to another ship and decrypted through the official CLI; a virtual browser verified a restored website-passkey signature.

The unmodified official Chrome extension 2026.10.0 created and used a website passkey on a separate owned test ship, then used it again after the ship and browser restarted. [Passkey evidence](../evidence/passkey/result.json). On another synthetic ship, an API-initiated password rewrap revoked an older official CLI profile; fresh official CLI SSO and unlock with the new password decrypted its retained item. [Cross-client evidence](../evidence/password-reauth/result.json). A synthetic PBKDF2 change to 650,000 iterations also let a fresh official CLI profile sign in and decrypt the retained item. [KDF compatibility evidence](../evidence/kdf-reauth/result.json). The official web-app KDF settings control and independent-client reauthentication after the owner's development-vault desktop change remain unverified. Physical iOS/Android devices and Windows/Linux desktop clients are not yet verified; do not claim those workflows from API support or Simulator evidence. Immediate push, organizations, shared vaults, Sends, API-key login and password login are outside this release. Authorization tokens and some password-derived management hashes can remain in Urbit history under the [accepted limitation](known-limitations.md).
