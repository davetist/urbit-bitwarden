## Qualifications and observed failures

1. **CLI first-attempt failure:** the first SSO attempt reported “Refresh Access token error.” A fresh profile then passed and completed the workflows above. Ordinary exchange, immediate sync and refresh checks passed afterward. The first failure's cause is unconfirmed; no claim of consistently reliable first-attempt SSO is made.
2. **Mobile consent usability:** in the iOS system browser at default scale, the approval button was beneath the bottom toolbar and the attempted scrolling did not expose it. Reducing Safari page scale allowed approval. Earlier consents also expired while native UI automation stalled and were restarted. Default-scale mobile approval needs a focused usability follow-up.
3. **Test-environment corrections:** an initially overlong temporary Unix-socket path was shortened; the iOS build needed the cached Mint executable on PATH; Electron inspector attachment was replaced by renderer-only automation. The desktop SSO browser inherited a stale localhost owner cookie, so the same handoff was opened in the isolated authenticated browser and completed through the normal OS callback. Native typing missed characters and notes accessibility assignment did not update the iOS model; native Paste followed by independent CLI decryption established the final edit.
4. **Connect harness regression:** the first full Connect native run failed because XCTest relaunched the preserved older app with the newer SDK framework. Retaining the validated old framework path during attachment, then removing it before updated-app launch, fixed the focused regression without weakening its assertions. The complete rerun is recorded separately in Connect.
5. **Invalid broad test discovery:** a generic Python discovery command imported standalone live-fixture runners and lacked local-socket permissions. Those failed prerequisites are not desk failures or successful live checks. The appropriate explicit offline suites were then run and passed. No journal/security validation is claimed from that attempt.

## Readiness boundary

The previous uncertainty about running official clients after the fixes and repository split is now resolved for the listed workflows and exact source pair. The first CLI failure and mobile consent workaround remain open reliability/usability qualifications.

Android installed-client acceptance, physical devices, App Store iOS, Windows/Linux desktop, password-protected JSON export, automatic save/update banners and elapsed-time fallback-sync behavior remain unqualified. Immediate push, organizations, attachments, Sends, passkeys and automatic trash expiry remain unsupported. The six-hour desktop/extension and 30-minute mobile fallback behavior is source-confirmed rather than timed by this run.

The 60-second access lifetime, 30-day absolute Connect grant and five-second retry grace remain unchanged. Authorization-token retention is the accepted limitation already documented; tokens do not decrypt vault passwords. Expanded request/journal/adversarial validation was not rerun, and this functional exercise is not a production security assessment. Connect still has its independent real-host, operator/developer, soak and seven-day trial gates.
